# أكاديمية نجد

موقع ثابت (HTML/CSS/JS) لطلاب جامعة الأمير مساعد بن عبدالرحمن.

| الصفحة | الملف |
|---|---|
| الرئيسية | `index.html` (و `home.html` تحوّل لها للروابط القديمة) |
| الخطط الدراسية | `plans.html` |
| الجدول الدراسي | `schedule.html` |
| حاسبة المعدل | `gpa.html` |
| الشروحات | `lessons.html` |
| التدريب التعاوني (مفتوحة للكل) | `coop.html` |
| المتجر (منتجات سلة/زد، مفتوحة للكل) | `store.html` |
| اختبر نفسك (اختبارات تفاعلية) | `quiz.html` |
| المقررات: بحث، «مقرراتك» من خطتك، وكل المقررات بالمستويات (مفتوحة للكل) | `courses.html` |
| دليل الطالب: الأنظمة واللوائح بكلام واضح (مفتوحة للكل) | `guide.html` |
| تقييم أعضاء هيئة التدريس (وتقييم المقرر لما يجي من صفحته `?c=`) | `ratings.html` |
| التقويم الأكاديمي (مفتوحة للكل) | `calendar.html` |
| حسابي | `account.html` |
| صفحة الخطأ 404 | `404.html` |
| لوحة الإدارة (للمشرف) | `admin.html` |
| تسجيل الدخول / إنشاء حساب | `login.html` / `register.html` |
| خطط كلية العلوم الإدارية والمالية (الصفحة الأصلية، بدون رابط في الموقع) | `college-plans.html` |

## الملفات المشتركة
- `assets/css/najd.css`: التصميم والألوان المشتركة (الهيدر، الفوتر، البطاقات، الأزرار).
- `assets/js/layout.js`: يبني الهيدر والفوتر في كل صفحة. روابط الصفحات تتعدل من `LINKS` في أول الملف.
- `assets/js/auth.js`: إعدادات Firebase، وتسجيل الدخول، ومزامنة التقدم مع Firestore.
- `assets/js/auth-forms.js`: نماذج الدخول والتسجيل.

## الدخول
- الخطط والجدول والمعدل والشروحات تحتاج تسجيل دخول.
- الرئيسية والتدريب التعاوني مفتوحة للكل.
- طرق الدخول: **حساب Gmail (قوقل)** أو **البريد الإلكتروني وكلمة المرور**.
- ملاحظة: القفل يصير في المتصفح (واجهة فقط). بيانات كل طالب نفسها محمية بقواعد Firestore.

## إعداد Firebase (مرة وحدة)
1. **Authentication ← Sign-in method**: فعّل **Google** و **Email/Password** (ما تحتاج خطة Blaze).
2. **Authentication ← Settings ← Authorized domains**: أضف النطاق اللي ينشر عليه الموقع (مثل `elite-122.github.io` أو نطاقك الخاص).
3. **Firestore Database**: أنشئ قاعدة البيانات، وبعدها من تبويب **Rules** الصق محتوى الملف `firestore.rules` واضغط **Publish**.

## لوحة الإدارة (`admin.html`)
فيها خمسة أقسام:
- **الإعلان:** شريط أعلى كل الصفحات.
- **المنتجات:** بطاقات في صفحة المتجر، وزر الطلب يفتح المنتج في سلة أو زد.
- **الشروحات:** فيديو يوتيوب أو PDF. الرابط محفوظ في `lessonLinks` ويقرأه بس المشترك، أو الكل لو الشرح مجاني.
- **المشتركين:** تفعّل اشتراك الطالب ببريده (`access/{البريد}`)، مع تاريخ انتهاء اختياري. البريد لازم يكون مؤكد.
- **التدريب التعاوني.**

ملاحظة: روابط يوتيوب «غير المدرجة» وروابط درايف يقدر المشترك يشاركها مع غيره. هذا حد طبيعي لأي موقع ثابت.

## إضافة مشرف
1. سجّل دخولك في الموقع وافتح `admin.html`. بيطلع لك رمز حسابك (UID).
2. في **Firestore Database** أنشئ مجموعة اسمها `admins`، و Document ID هو رمز حسابك، وأضف حقل `role` قيمته `owner`.
3. حدّث الصفحة، وتقدر بعدها تضيف الفرص وتعدلها وتحذفها.

## وش ينحفظ في الحساب؟
مستند `users/{uid}` فيه: الخطة (`najd_plans_v1`)، والمعدل (`najd_gpa_v1`)، والجدول (`stq_schedule_v1`)، ونتائج الاختبارات (`najd_quiz_v1`)، وخطة المذاكرة (`najd_study_v1`)، ودفتر الأخطاء (`najd_mist_v1`)، واختيارات «وش أسجل الفصل الجاي؟» (`najd_next_v1`).
الأدوات تشتغل بدون حساب وتحفظ في المتصفح. ولما يسجل الطالب دخوله، يتزامن تقدمه بين أجهزته تلقائيًا.

## تنبيهات الدراسة (الإيميل وإشعار الجوال)
بعد ما يسجل الطالب، تطلع له نافذة «خطوة أخيرة: خلّنا نذكّرك». يفعّلها بضغطة، أو يكمل بدونها ونسأله مرة ثانية لما يضيف أول اختبار. يعدّلها متى ما يبي من «حسابي ← تنبيهاتي».

**كيف يعرف إن عند الطالب اختبار بكرة؟** الجدول وخطة المذاكرة ودفتر الأخطاء محفوظة في حسابه (`users/{uid}.data`). GitHub Actions يشغّل `reminders/run.js` الساعة 7 الصبح و7 و8 و9 مساءً بتوقيت الرياض. يقرأ بيانات كل طالب مفعّل التنبيهات ويرسل له في الساعة اللي اختارها:
- **المساء:** اختبار بكرة (مع الفصول اللي باقية عليه)، وواجب بكرة أو بعد يومين، وأسئلة جا وقت مراجعتها.
- **الصبح:** اختبار اليوم، وموعد اليوم، وجلسات مذاكرة اليوم.
- إذا ما عنده شيء، ما يوصله شيء.

ما يحتاج خطة Blaze ولا بطاقة: قراءة القاعدة والإيميل وإشعار الجوال كلها مجانية، وGitHub Actions مجاني للمستودع العام.

**الملفات:**
- `assets/js/notify.js`: النافذة والإعدادات.
- `reminders/`: الإرسال. `build.js` يجهّز التذكير، و`run.js` يقرأ ويرسل.
- `.github/workflows/reminders.yml`: الأوقات.
- `unsubscribe.html`: رابط «إيقاف التنبيهات» في آخر كل إيميل. يشتغل بدون دخول، بشرط المفتاح اللي في الرابط (القاعدة في `firestore.rules`).
- `sw.js`: يعرض إشعار الجوال.

اختبار محلي بدون إرسال: `npm ci --prefix reminders && node reminders/test.js`

**زر «جرّب تنبيه الحين»:** يسجّل طلب في حساب الطالب، والتشغيل اللي كل ساعة يرسل له إيميل وإشعار تجريبي.

**التشغيل (مرة وحدة):**
1. **قواعد القاعدة:** Firestore ← Rules، الصق محتوى `firestore.rules` الجديد واضغط Publish. (فيها قاعدة رابط إيقاف الإيميل).
2. **مفتاح حساب الخدمة:** Firebase ← Project settings ← Service accounts ← Generate new private key. ينزل ملف JSON، حط محتواه كامل في GitHub ← Settings ← Secrets and variables ← Actions ← New repository secret باسم `FIREBASE_SERVICE_ACCOUNT`. وبعدها احذف الملف من جهازك.
3. **كلمة مرور تطبيق** لإيميل الموقع najdacdemy@gmail.com: myaccount.google.com ← الأمان ← التحقق بخطوتين (لازم يكون مفعّل) ← كلمات مرور التطبيقات. حطها في سر باسم `GMAIL_APP_PASSWORD`.
4. **مفتاح إشعارات الجوال:** Firebase ← Project settings ← Cloud Messaging ← Web Push certificates ← Generate key pair. المفتاح العام في `window.NAJD_PUSH_KEY` في `assets/js/layout.js` (مضاف). في الآيفون الإشعار يشتغل بس من التطبيق المثبّت (iOS 16.4 وأحدث).
5. **التوقيت بالضبط (cron-job.org):** جدولة GitHub تتأخر ساعات أحيانًا، فخدمة cron-job.org المجانية تشغّل التنبيهات كل نص ساعة:
   - **مفتاح GitHub:** Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token. المستودع: هذا بس. الصلاحيات: Actions ← Read and write. ما يحتاج غيرها.
   - **المهمة في cron-job.org:** الرابط `https://api.github.com/repos/Elite-122/seu-study-plan/actions/workflows/reminders.yml/dispatches`، كل 30 دقيقة، الطريقة POST، والهيدرز `Authorization: Bearer <المفتاح>` و`Accept: application/vnd.github+json` و`X-GitHub-Api-Version: 2022-11-28` و`Content-Type: application/json`، والمحتوى `{"ref":"main","inputs":{"mode":"auto"}}`.
   - `auto` يختار التذكير حسب ساعة الرياض (7 ص، و7 و8 و9 م)، وباقي الأوقات يرسل التجارب المطلوبة بس. جدولة GitHub تبقى احتياط، والتذكير ما يتكرر (`notify.last`)، واللي يتأخر كثير ما ينرسل (`onTime` في `run.js`).

**التجربة:** من حسابي اضغط «جرّب تنبيه الحين»، وبعدها GitHub ← Actions ← Study reminders ← Run workflow (اختر `tests`). يوصلك الإيميل خلال دقيقة.

**ملاحظات:**
- جدولة GitHub تتأخر أحيانًا ساعات أو تنتخطّى، عشان كذا التشغيل الأساسي من cron-job.org (الخطوة 5).
- GitHub يوقف الجدولة لو المستودع ما تعدّل 60 يوم، ويرسل إيميل تنبيه. ترجعها من Actions ← Study reminders ← Enable workflow.
- Gmail يسمح بحوالي 500 إيميل باليوم. لو زاد عدد الطلاب عن كذا، نحتاج خدمة إرسال إيميلات.

## الوضع الداكن واللغة
- زر 🌙/☀️ في الهيدر يبدّل بين الوضع الفاتح والداكن، ويتذكر اختيار الزائر. الوضع الأساسي فاتح، والداكن بس لو اختاره الزائر.
- زر EN/ع يبدّل لغة الموقع كامل. الترجمة في `assets/js/i18n.js`: كل سطر نص عربي وترجمته. لو أضفت نص جديد، أضف ترجمته هناك.
- المحتوى اللي تكتبه من لوحة الإدارة (أسماء المنتجات والجهات والشروحات) يظهر مثل ما كتبته.

## صفحات المقررات (`c/<الرمز>.html`)
صفحة ثابتة لكل مقرر عشان قوقل يقرأها. **لا تعدّلها بيدك.** تنبني من:
- `tools/course-template.html`: شكل الصفحة.
- `tools/course-desc.json`: أوصاف المقررات من ملفات الخطط الرسمية للجامعة (عربي وإنجليزي).
- `assets/js/teaching-data.js`: مين يدرّس وش، من صفحة البحث عن الشعب في نظام التسجيل. حدّثه كل فصل.
- بيانات المقررات والخطط في `assets/js/`.

بعد أي تعديل عليها شغّل `python3 tools/build-courses.py` (يبني الصفحات و`sitemap.xml`).

## التقويم الأكاديمي (`calendar.html`)
- **الأساس:** التقويم الرسمي لمرحلة البكالوريوس من موقع الجامعة، محفوظ في `assets/js/seu-calendar.js` (الفصل الأول والثاني والصيفي). الصفحة تفتح على الفصل اللي اليوم داخله، وإذا خلص تنتقل للي بعده لحالها، وتعلم الطالب إنها نقلته.
- **إعلانات العمادة:** لو أعلنت عمادة القبول والتسجيل موعد يختلف عن التقويم، الإعلان هو المعتمد. أضفه في `tools/seu-calendar-overrides.json` (العنوان بالضبط كما في التقويم، والتاريخ الجديد، ورابط الإعلان)، ويطلع جنب الموعد «مدّدته العمادة» أو «عدّلته العمادة» مع رابط الإعلان والموعد القديم.
- **التحديث:** `python3 tools/seu-calendar.py 1448` يسحب التقويم من الموقع ويبني الملف. لو عدّلت الإعلانات أو الترجمة بس: `python3 tools/seu-calendar.py 1448 --build`. لما تنشر الجامعة تقويم 1449، شغّله بـ`1449`. وبعدها `tools/set-version.py`.
- **الترجمة:** عناوين المواعيد بالإنجليزي في `tools/seu-calendar-en.json`، والأداة تنبهك لو فيه عنوان جديد بدون ترجمة.
- **لوحتي:** بطاقة «التسجيل للفصل الجاي» تاخذ موعد التسجيل من نفس الملف، وتطلع قبله بأسبوعين.

## دليل الطالب (`guide.html`)
- **المحتوى** في `assets/js/guide-data.js`: ثمان أقسام بالعربي والإنجليزي، وكل جواب معه مصدره الرسمي (`SRC`) ورقم المادة.
- **المصادر:** القواعد التنفيذية للائحة الدراسة والاختبارات (يناير 2026)، والدليل الشامل للخدمات الإلكترونية، والأسئلة الشائعة، وضوابط أعذار الغياب، ودليل الإجراءات الأكاديمية. لو صدرت لائحة أحدث، عدّل الأجوبة وغيّر `updated`.
- **مواعيد كل قسم** تجي من التقويم الرسمي (`live` = جزء من عنوان الموعد في التقويم).
- **دليل البلاك بورد** المفصل ينتظر صور الشاشات من صاحب الموقع.

## صفحة المقررات (`courses.html`)
- تقرأ الخطط من `plans-data.js`، والوصف القصير من `assets/js/course-desc.js` (يتولد مع `tools/build-courses.py`)، ومين يدرّس من `teaching-data.js`، ومتوسط التقييم من التجارب المعتمدة.
- «مقرراتك» تاخذ التخصص والمقررات المنجزة من خطة الطالب (`najd_plans_v1`)، واختيار التخصص فيها يحفظه للخطة. «كل المقررات» تصفح بس وما تغيّر تخصصه.

## بعد أي تحديث للملفات
شغّل `python3 tools/set-version.py` عشان يتحدث رقم الإصدار في روابط الملفات، والمتصفحات تجيب النسخة الجديدة على طول. ولو عدّلت بيانات المقررات، شغّل `tools/build-courses.py` قبله.

## الأقسام الجديدة في لوحة الإدارة
- **الاختبارات:** تكتب الأسئلة كنص: السؤال في سطر، وتحته الخيارات، و`*` قبل الإجابة الصحيحة، وسطر فاضي بين الأسئلة. وسطر يبدأ بـ «شرح:» اختياري. الأسئلة محفوظة في `quizData` ويقرأها المشترك فقط (أو الكل لو الاختبار مجاني).
- **التقويم:** مواعيد زيادة على التقويم الرسمي (`calendar`)، مثل ورشة أو تنبيه. تطلع للطلاب بعلامة «من نجد». التقويم الرسمي نفسه ما يحتاج إدخال (شوف «التقويم الأكاديمي» تحت).
- **التقييمات:** التقييم بالأرقام ينشر مباشرة، والتعليق المكتوب يبقى معلّق لين توافق عليه. تقييم واحد لكل طالب لكل مقرر أو عضو.
- **الأعضاء:** أسماء أعضاء هيئة التدريس اللي ينقيّمون (`instructors`).
- **آراء الطلاب:** تظهر في الرئيسية (`testimonials`)، والقسم يختفي لو ما فيه آراء.
